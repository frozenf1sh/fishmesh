# 阶段 38：R6G 最终压测矩阵与仓库收缩

## 1. 范围

本阶段把最终真实集群验证收敛为 `fishmesh-client bench`，并移除不再参与正常开发的历史测试入口。
Lite Gateway 仍是主交付物；`fishmesh-epp`、`internal/serving/llmd` 和 integrated 配置保留，但 Standard
mode 暂不进入默认 manifest 门禁。

## 2. 最终压测契约

`bench` 支持 JSON 计划和内置计划。每个 scenario 独立声明：

- `prefix_bytes`：prompt 前缀长度档位；
- `batches`、`batch_size`：请求数量与顺序批次；
- `concurrency`：批次内部并发上限；
- `same-prefix`、`different-prefix`、`mixed-prefix`：前缀复用分布；
- mixed 模式的热点/独立前缀比例。

执行时不发送 session key。每个批次顺序执行，批次之间默认等待 KVEvents/replay 收敛；每个请求只记录
形状元数据、固定 FishMesh 决策头、TTFT、总耗时和错误，不记录 prompt、API key 或原始 SSE。

```bash
go run ./cmd/fishmesh-client bench \
  --plan configs/final-pressure.json \
  --output-dir artifacts/bench/final-pressure
```

产物为 `plan.json`、`requests.jsonl`、`report.json` 和 `report.md`。报告按 scenario 和 batch 汇总成功率、
TTFT/总耗时分位数、KV 状态、route reason、backend 分布和 cached prefix tokens；KV unavailable 不会被当作零命中。

## 3. 清理结果

移除：

- analyst、Diagnostics domain 和 analyst deployment；
- 独立 simulator 及依赖它的 simulator E2E；
- 旧 loadgen、一次性 R6A KV 探针和旧 loadgen validation Job；
- 默认 manifest 对历史 experiment/validation 的隐式门禁。

集群 smoke/模型预热保留为显式 `make manifest-validation`，Standard 配置保留为显式
`make manifest-standard`。历史实验结论仍由阶段文档和 Git 历史承载。
