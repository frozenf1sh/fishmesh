# 阶段 71：R6H 高负载滚动重启复验

## 1. 目标

复用旧 R6H 的高负载长上下文 mixed 矩阵，在每个 formal arm 滚动重启 vLLM 与 Gateway，判断旧的 warm-cache
收益是否依赖跨 arm 残留状态，并消除 active admission 作为混杂因素。

## 2. 实施

- 增加 `configs/r6i28-r6h-rolling.json`：保留 R6H 的 4/12 KiB、same/different/mixed、并发 8/16、392 请求/run。
- 增加 R6I-28 active overlay：当前 Gateway 镜像、active admission 16/8/64、max in-flight 64、16 upstream connections。
- 增加 `configs/r6i29-r6h-rolling-off.json` 与 off overlay：admission 关闭，使用有效的 64/8/64 配置。
- 将滚动重启脚本参数化为 plan、overlay、run prefix 和 arm 目录，保留默认 R6I-27 行为不变。
- 每个 arm 等待两个 vLLM Pod Ready、KV arm 等待两个 valid backend，并在退出时恢复 declarative baseline。

## 3. 结果

R6I-28 active 的 pooled TTFT P95 为 `642.48 -> 707.13 ms`（`+10.06%`，CI `[-1.29%, +21.32%]`）；
R6I-29b off 的 pooled TTFT P95 为 `658.99 -> 709.66 ms`（`+7.69%`，CI `[-0.82%, +16.61%]`）。
两组共 `3136/3136` 成功，KV `784/784 available`，rejection 为 0。same-4k/same-12k 在 off 控制组分别
下降 `17.18%/36.70%`，mixed-4k/mixed-12k 分别上升 `9.27%/1.41%`；当前版本没有复现旧 R6H mixed
场景的 `-62.3%/-84.3%` P95 收益。

## 4. 结论与边界

active 与 off 方向一致，动态 admission 不是主因。当前复验排除了“旧 arm 缓存残留导致旧收益”的解释，
但旧 R6H 使用 `r6i1-load-gates-r1`、本轮使用 `r6i24-admission-kv-bypass-r1`，且旧实验未重启进程；
因此尚不能将差异归因到某一个服务提交。下一步若需要完成因果拆分，应在同一 workload 下做旧/当前 Gateway
镜像 × warm/reset 的 2×2 消融，并继续采集 vLLM `/metrics` 的 prefix-cache、queue/running 和 GPU 归属指标。
