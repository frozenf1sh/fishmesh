# 08｜请求路径可靠性

状态：代码、本地测试和真实 K3s 兼容性验证均已完成。

## 这一阶段解决什么问题

上一阶段已经能“选后端”，但一个长期运行的网关还必须回答：

- 请求太多时，是继续堆积，还是及时拒绝？
- 某个后端连续连接失败时，是否还要继续把请求发给它？
- Pod 被删除后，为它创建的连接、计数器和指标会不会一直留在内存里？
- 指标值为 `0` 时，究竟是“确实为 0”，还是“根本没采到”？
- 客户端取消请求后，能否立即释放资源？流已经开始后会不会错误地重试？

本阶段不增加新的调度算法，而是把现有请求路径变成有界、可恢复的状态机。

## 1. Admission：入口限流

Gateway 使用一个固定容量的 permit channel 表示“当前可以同时处理多少个 `/v1` 请求”。

- 有空位：请求进入路由和代理流程；
- 没空位：立即返回 `429 Too Many Requests`、`Retry-After: 1` 和
  `X-FishMesh-Route-Reason: admission-capacity`；
- 请求结束或取消：permit 必定归还。

它类似餐厅只有固定数量的座位：坐满后直接告诉新客人稍后再来，而不是让队伍无限增长并
最终耗尽内存。

## 2. Circuit breaker：临时绕开故障后端

每个直接 endpoint 都有一个只记录 transport outcome 的小型 circuit：

1. 连接、超时或上游流读取失败记为 `1`；成功记为 `0`；
2. 使用 EWMA 让最近的失败权重更高；
3. 样本数和错误率同时达到阈值后，circuit 在短时间内打开；
4. 打开期间该 endpoint 仍是成员，但暂时不具备被选择的资格；
5. 时间到后清空窗口并重新接受请求。

客户端主动取消属于下游行为，不会惩罚 backend。HTTP 4xx/5xx 已经成功建立连接并收到
响应，也不作为本版 transport circuit 的失败。

bounded affinity 遇到 circuit-open 会临时 spillover，但不会改写 preferred backend；故障
窗口结束后可以恢复原有 affinity。

## 3. Endpoint state GC：Pod 消失后回收状态

Gateway 周期性读取 resolver 的内存快照，并用当前 backend ID 集合回收已删除 endpoint 的：

- affinity registry entry；
- HTTP client 和 idle connections；
- local in-flight counter；
- circuit state；
- observation 和 Prometheus backend label。

如果 endpoint 删除时仍有请求在执行，先保留它的状态；最后一个请求释放计数后再清理，避免
关闭仍在使用的 client。

## 4. Per-field sample：区分 0 和缺失

queue/running 不再只是一个 `float64`，而是：

```text
Sample {
  value
  valid
  observed_at
  source
  error
}
```

因此 `value=0, valid=true` 表示“确认队列为空”；`valid=false` 表示“没有采到或已经过期”。
只有所有候选 backend 的 queue sample 都有效时，queue 才能参与 spillover。

## 5. 取消、超时和重试边界

- client context 会传给 upstream request；
- client cancellation 记为内部状态 `499`，用于 metrics，不打开 circuit；
- 请求在响应头之前超时返回 `504`；其他 transport error 返回 `502`；
- response headers 一旦发给客户端，后续 stream failure 只记录日志、metric 和 circuit
  outcome，绝不透明重试，否则可能生成两份 token。

## 配置默认值

| 环境变量 | 默认值 | 含义 |
| --- | --- | --- |
| `FISHMESH_MAX_INFLIGHT_REQUESTS` | `128` | Gateway 同时处理的 `/v1` 请求上限 |
| `FISHMESH_MAX_CONNS_PER_HOST` | `32` | 每个 backend 的 TCP 连接上限 |
| `FISHMESH_CIRCUIT_EWMA_ALPHA` | `0.5` | 最新 transport outcome 的 EWMA 权重 |
| `FISHMESH_CIRCUIT_ERROR_THRESHOLD` | `0.6` | 打开 circuit 的错误率阈值 |
| `FISHMESH_CIRCUIT_MIN_REQUESTS` | `3` | 判断前的最少样本数 |
| `FISHMESH_CIRCUIT_OPEN_DURATION` | `10s` | 临时隔离时长 |

显式配置为非法值会让 Gateway 启动失败，不静默回退。

## 已完成的本地验证

- admission 满载时立即 429，permit 最终归还；
- client cancellation 到达 upstream，且不创建 circuit failure；
- 连续 transport failure 打开 circuit，下一请求 spill 到另一个 endpoint；
- circuit spillover 不改写 affinity preference；
- response headers 后的 stream failure 不重试；
- endpoint 删除后连接池、counter、circuit 和 affinity state 被回收；
- queue sample 能区分 observed zero 与 missing/stale；
- `go test -race ./...`、`go vet ./...`、`go build ./...` 和全部 Kustomize 渲染通过。
