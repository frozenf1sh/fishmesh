# 阶段 25：R6D 有限性能对照

> 日期：2026-08-12
> 类型：真实集群 correctness/profile 证据（非生产性能声明）
> 状态：已完成

## 1. 范围与方法

本阶段没有新增产品功能。复用已有 direct `qwen-vllm-baseline` Service、Gateway `load-aware`、
Gateway `exact-cache-load`、`internal/workload/loadgen` 和 vLLM/Gateway `/metrics`。为保证每个
treatment 都使用同一独立 Gateway image，临时 overlay 仅切换已有 routing mode；最终已应用
`r6d-bounded-affinity`，集群当前 `FISHMESH_ROUTING_MODE=bounded-affinity`。

固定随机 treatment 顺序为：Service-1、load-only-1、exact-1、Service-2、exact-2、load-only-2、
Service-3、load-only-3、exact-3。每个 attempt 均使用 loadgen 默认 workload：200 requests、并发 4、
8 个 4096-byte 公共 system prompt group、32 max tokens、90 s timeout、`keep-alive=false`；唯一的
命令行差别是 endpoint、run provenance。九份完整 JSONL（metadata、每请求与 summary）保留在实验机
`/tmp/r6d-*-round-*.jsonl`，未放入 Git；所有 1,800 请求成功，故没有失败 attempt 可另列。

TTFT 由 SSE 首个非终止 event 测量；吞吐是两 vLLM Pod 的 `generation_tokens_total` delta / attempt
wall time；命中率是两 Pod `prompt_tokens_cached_total / prompt_tokens_total` delta，即**cached token
share 而不是逐请求 boolean hit rate**。Gateway CPU 是 `process_cpu_seconds_total` delta / wall time，RSS
为 attempt 后采样平均。现有产品指标没有每条 KV event 的 publish→apply latency；exact 仅报告既有
`kv_cache_freshness_seconds` 的末尾最大值（0.83–1.55 s），它是 replay-confirmed freshness，不可误称
event latency。R6A 的 0.678 ms 是另一轮探针结果，不能归因给本表。

## 3. 结论与环境边界

本配置下 exact 保持 correctness：Gateway restart 后出现的 8 个 unknown/replay 样本都明确选择
`exact-load-fallback-v1`，没有把 unknown/stale 写成 exact cache hit；稳定后 592 个请求使用 exact
policy。代价也清晰可见：在 Qwen2.5-0.5B 的短生成 profile 中，Render、body replay、KV lookup 和
Gateway 路径使 exact 的 TTFT/吞吐不优于 direct Service。此结果没有触发代码优化或参数调节；R6D 的
交付是性能边界证据，而非用更大 max_tokens、更低并发或更大 workload 矩阵放大差异。

环境为单 RTX 4060 的 time-slicing、Qwen2.5-0.5B-Instruct、两个共享 vLLM 副本、单 Gateway，且
loadgen 与推理同在 GPU node。它只可作为 correctness/profile 证据，**不构成生产性能、容量或跨硬件
结论**。当前没有 per-event latency 或逐请求 cached-prefix label 的 production metric，下一阶段如需
作出性能归因必须先单独定义可观测契约，不能由累计 counter 推断。

## 4. 验证与恢复

- 每次 Gateway 配置切换均声明式 apply 并等待 rollout Ready；
- 实验后已声明式恢复 `deploy/experiments/r6d-bounded-affinity`，Gateway 与两个 vLLM 副本均 Ready；
- `go test -race ./...`、`go vet ./...`、`go build ./...`、`make manifest` 均通过；race 输出尾部随提交报告。
