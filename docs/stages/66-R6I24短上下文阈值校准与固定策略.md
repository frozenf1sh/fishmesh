# 阶段 66：R6I-24 Short-context threshold calibration：短上下文阈值校准与固定策略

## 交付

- 新增 `configs/r6i24-kv-short-threshold-sweep.json`，复用已校准的 512/1024/2048/3072 token 请求档。
- 新增 512/1024/2048/3072 阈值 overlay，并额外验证带安全裕量的 `576` 候选 overlay。
- 完成同一 vLLM generation 下 threshold 0 与 threshold 576 的两轮 paired repeat；所有有效请求 640/640 成功，
  无 admission rejection。
- 明确阈值判断使用精确 tokenization 后的实际 token；名义 512/1024/2048/3072 会因实际 513/1030/2049–2053/3078
  产生覆盖不足，必须加入 profile-specific guard band。

## 结论

阈值采用“实验确定 + profile-scoped 固定”的混合方案：

- 不使用一个跨模型、跨 GPU、跨 vLLM 的全局常量；
- 不在在线请求路径中根据瞬时指标动态改阈值；
- 由 shadow 观测提出重校准建议，经过独立 paired A/B 与变更流程后更新 deployment 配置；
- 当前 RTX 4060/Qwen2.5-0.5B/vLLM 0.23.0 profile 的候选是 `576`，只覆盖 512-token 极短请求；1024 及以上继续
  保留 KV-aware locality；默认仍为阈值 0，等待更多轮次 promotion gate。

两轮 pooled TTFT P95 为 `940.87 → 839.14 ms`（`-10.81%`），但 bootstrap 95% CI 为 `[-26.61%, +22.40%]`，
因此不能宣称整体性能收益已经确定。按场景，512 档平均 P95 下降 `53.32%`，1024/2048/3072 分别为
`+6.93%/-0.18%/+0.74%`；这支持“只旁路极短上下文”的保守策略。

完整数据与 exclusions 见 [`2026-08-16-r6i24-kv-short-threshold.md`](../experiments/2026-08-16-r6i24-kv-short-threshold.md)。
