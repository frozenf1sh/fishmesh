# 11｜R2 原子 I/O 能力边界

状态：代码迁移和本地验证完成；没有改变运行协议、调度算法或部署。

## 这一阶段解决什么问题

R1 已把核心类型放回各自 owner，但几个连接外部系统的包仍不统一：`endpoint` 名称只描述了
数据结果，没有表达“发现”能力；部分具体实现结构体直接暴露给 Gateway；Kubernetes 字段、
环境变量、HTTP header 和 Prometheus label 仍散落为字符串。

R2 只整理边界，不修改请求的选择结果。目标是让第一次阅读代码的人先看同包名文件，就知道
该包提供什么能力；需要了解网络和 Kubernetes 细节时，再进入 `_impl.go`。

## Discovery 的新布局

`serving/endpoint` 已更名为 `serving/discovery`：

| 文件 | 内容 |
| --- | --- |
| `discovery.go` | `Resolver`、status、公开配置；不含实现流程 |
| `static_impl.go` | 实验和单测使用的不可变静态快照 |
| `endpointslice_impl.go` | resolver 生命周期、refresh/watch 编排、freshness |
| `endpointslice_api_impl.go` | Kubernetes REST 请求、认证和 watch 解码 |
| `endpointslice_types_impl.go` | EndpointSlice wire DTO 与 backend 构造 |

原来一个文件同时包含生命周期、HTTP、JSON DTO 和地址转换，超过 400 行。拆分后，修改某一层
不需要先理解其他层。`backend.MetadataPodName` 则成为 discovery 到 identity 的明确 metadata
契约，避免两边分别书写 `pod_name`。

## 其他 I/O domain

- `identity.go` 只暴露 `Enricher`、`Identity` 和 `Config`；Kubernetes 具体类型保持私有，调用方
  通过 `NewKubernetes` 获取接口；
- `observation.go` 只暴露采样、reader/collector 契约和配置；vLLM Prometheus 具体 collector
  保持私有，调用方通过 `NewPrometheus` 获取接口；
- `transport.go` 只暴露连接池接口和配置；`transport_impl.go` 负责锁、HTTP client 和 idle
  connection 生命周期，Gateway 不再持有具体 `*Pool`。

这些接口不是为了目录对称而创建：三种能力都连接外部状态、存在替换实现或需要在测试中注入，
因此接口边界有实际用途。

## 协议字面量

本阶段集中管理了三类容易拼错、又必须保持兼容的值：

- `FISHMESH_*` 环境变量和默认值；
- `X-FishMesh-*`、hop-by-hop header、SSE 终止标记和 HTTP route；
- Prometheus metric name、label name，以及 vLLM 指标兼容名称。

Discovery mode 和 observation mode 也改为命名类型。环境变量的实际名称和值、HTTP header、
metric name 均未改变。

## 自动依赖门禁

原子 domain 的当前依赖为：

```text
backend     -> no FishMesh internal package
circuit     -> backend
routing     -> backend + observation
identity    -> backend + platform/kubernetes
observation -> backend + identity
transport   -> backend
discovery   -> backend + platform/kubernetes
```

`internal/serving/architecture` 已同步检查 `discovery`，旧 `endpoint` 包不再存在。
