# 10｜R1 核心类型与依赖方向

状态：代码迁移和本地验证完成；没有改变运行行为或集群部署。

## 这一阶段解决什么问题

过去 `routing` 同时拥有 Backend、Identity、Observation、Sample、Snapshot、具体路由策略和
Circuit。其他包只是想描述一个 backend 或观测值，也必须 import routing，很难从 import 判断
一个包是否真的依赖路由算法。

R1 先处理最底层的类型所有权，不急着拆 Gateway 主流程。这样后续 R2–R4 每移动一个能力时，
编译器都能帮助我们发现错误依赖。

## 新的类型所有权

| 类型/能力 | 新 owner | 说明 |
| --- | --- | --- |
| `ID`、`Backend` | `serving/backend` | 只描述稳定身份、地址和 discovery metadata |
| `Identity`、identity status | `serving/identity` | Pod、Node、Ready 和声明 GPU request |
| `Sample[T]`、backend observation/status | `serving/observation` | 区分真实零值、缺失和过期采样 |
| `Mode`、`Policy`、`Reason`、`Snapshot`、`Decision` | `serving/routing` | 只解释输入并选择 backend |
| transport outcome EWMA | `serving/circuit` | 不再作为 routing 的附属类型 |

`backend.ID` 是命名类型，不再使用任意 string 充当所有 backend 标识。跨到 HTTP header 或
Prometheus label 边界时才显式转成 string。

Discovery、Identity 和 Observation 现在各自拥有独立 typed status。以前三种含义不同的状态
共用 `routing.ObservationStatus`，容易让 discovery degradation 被误解成 metrics degradation。

## Routing 文件布局

`routing.go` 只保留公开契约、typed constants、工厂和通用 eligibility。具体策略分别位于：

- `service_impl.go`；
- `prefix_affinity_impl.go`；
- `load_aware_impl.go`；
- `bounded_affinity_impl.go`。

每个实现都通过编译期断言声明自己实现 `Strategy`；bounded affinity 额外声明
`BackendReconciler`。路由 reason 和 policy 不再散落为生产代码字符串。

## Circuit 文件布局

新的 `serving/circuit` 提供：

- `Breaker` 小接口；
- `Config` 和默认配置；
- `OutcomeSuccess`、`OutcomeFailure` typed outcome；
- `Record`、`IsOpen`、`Reconcile`、`Remove` 和 `Len`。

未知 outcome 不会被静默当成成功样本。客户端取消和 HTTP status 仍在 Gateway 边界完成分类，
本阶段没有改变原有熔断算法、阈值或开放时长。

## 自动依赖门禁

`internal/serving/architecture/architecture_test.go` 使用 `go list` 检查原子 domain 的直接 import。
当前强制：

```text
backend     -> no FishMesh internal package
circuit     -> backend
routing     -> backend + observation
identity    -> backend + platform/kubernetes
observation -> backend + identity
transport   -> backend
endpoint    -> backend + platform/kubernetes（R2 已更名为 discovery）
```

以后如果 routing 重新 import Gateway/Kubernetes，或者 transport 再次通过 routing 获取 Backend，
`go test ./...` 会直接失败。

## 保持不变的行为

- 环境变量名称和值不变；
- HTTP/SSE 请求、header 和 metrics 名称不变；
- affinity、spillover、fallback 和 circuit reason 值不变；
- admission、连接上限、timeout 和 endpoint GC 语义不变；
- 部署清单和 K3s 运行镜像不变，因此本阶段不需要重启集群。
