# 阶段 70：R6I-27 双层滚动重启与随机输入长上下文复验

## 交付

- benchmark 增加 `randomize_request_order` 和 `input_sequence`：同一 seed 下 LB/KV 使用完全相同的
  场景内随机输入顺序，不同 replicate 使用不同 seed；scenario order 继续由 workload seed 确定性打乱。
- 新增 3072/3584 长上下文快速复验计划，6 场景、每 arm 96 请求、两个 replicate，共 384 正式请求。
- 新增自动化脚本：每个 arm 先声明式应用 overlay，再滚动重启 vLLM 与 Gateway；vLLM 强制检查
  `RollingUpdate/maxSurge=0/maxUnavailable=1`，KV arm 等待两个 backend replay valid 后才开始。
- Gateway 使用每个 arm 唯一 runtime annotation，确保本地 KV hash/index、subscriber 和 admission state
  不跨 arm 残留；vLLM 使用每个 arm 唯一 annotation，确保 GPU prefix cache 不跨 arm 残留。

## 真实结果

- 四个 arm 均 96/96 成功，纯 LB/KV pooled TTFT P95 为 `189.81/191.35 ms`，变化 `+0.81%`，
  bootstrap CI `[-15.45%, +38.22%]`，跨 0。
- KV `192/192` 为 `available`，cached-prefix samples `192/192`；LB `not-requested` 不解释为真实 miss。
- 3072 shared P95 下降 `39.20%`，3584 shared 上升 `49.30%`；低并发长上下文仍没有稳定整体收益。
- accepted QPS `1.720/1.715`，Little's Law W `185.76/192.72 ms`，两侧 rejection 均为 0。
- 结束后已恢复 load-balanced/admission-off 基线，Gateway 与两个 vLLM Pod 均 Ready、restarts=0。

完整数据见 [`2026-08-16-r6i27-long-context-rolling.md`](../experiments/2026-08-16-r6i27-long-context-rolling.md)。

## 边界

本阶段证明了“已有 vLLM KV cache 或 Gateway KV index 残留”不是 R6I-26 结果的充分解释；但 LB 真实 vLLM
prefix hit 仍未由直接 vLLM metrics 证明，且低并发样本量较小。下一步应在同样的双层滚动重启纪律下，
增加 vLLM `/metrics` 与 Pod/GPU runtime exporter，并做更高 arrival/concurrency 的长上下文阶梯。
