# 阶段 44：R6I-4 决策证据与对比报告

## 1. 范围

本阶段补齐 static TTFT 路由的请求级证据、低基数指标和多轮 A/B 汇总工具。它不改变路由选择，
不读取或保存 prompt、Token IDs、prefix identity 或任意非 allowlist upstream header。

## 2. 请求级证据

Gateway 在已有 `X-FishMesh-*` allowlist 中新增：

- prompt/cached/uncached token 数；
- estimated TTFT、valid、confidence、version 和 typed reason；
- load valid、sample age、queue、running、local in-flight；
- 本次候选集中被 HardOverload 排除的数量。

`fishmesh-client` 将这些固定数值字段写入 `requests.jsonl`，因此每个真实 TTFT 都能与当时的 estimate
和负载快照配对；原始请求内容仍不进入产物。

## 3. Prometheus

新增指标只使用固定枚举标签：

- `static_estimator_selections_total{confidence,estimator_reason}`；
- `static_estimated_ttft_seconds`；
- `static_estimator_absolute_error_seconds`；
- `hard_overload_selections_total{outcome}`。

estimate 与实际首 SSE 事件的绝对误差在请求完成时记录。`outcome` 仅区分 `partial` 和 `all`，不把
backend、prompt 或 profile 内容放入高基数标签。

## 4. Compare 交付

`fishmesh-client compare` 接受可重复的 `--baseline` 和 `--treatment`，读取 request-level JSONL，输出：

- pooled TTFT P50/P95/P99；
- 跨轮 P95 的中位数；
- 成功/失败请求数；
- estimator MAE 与 absolute-error P95；
- 固定 seed 的 bootstrap TTFT P95 delta 95% CI。

结果同时生成 `comparison.json` 和 `comparison.md`。raw JSONL 继续位于 Git 外，评审后的 compact report
才进入仓库。

## 5. 验证与边界

- requestpath、Gateway header/metrics、client allowlist 和 compare 统计均有 race tests；
- bootstrap seed 固定，重复输入得到相同区间；
- 本阶段没有 rollout、GPU 请求或性能结论；
- 完整 Git/image/Pod/vLLM/config/seed/cache generation metadata 在 R6I-5 与 cache 隔离协议一起完成。

## 6. 下一阶段

R6I-5 将 workload 从 byte 长度推进到实际 prompt token 证据，并用 run nonce、cache generation 和
`cold/controlled-warm/steady-warm` 三种状态阻止 paired treatment 复用上一轮 KV cache。
