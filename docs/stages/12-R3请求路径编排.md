# 12｜R3 请求路径编排

状态：代码迁移和本地验证完成；HTTP、路由原因、fallback 和 circuit 算法保持不变。

## 这一阶段解决什么问题

R2 后原子能力已经分包，但 Gateway 仍亲自完成 backend membership、local in-flight、circuit、
观测快照和 fallback。这意味着未来 EPP adapter 若想复用调度，仍要复制 Gateway 的核心流程。

R3 新建 `internal/serving/requestpath`。它是应用编排层：不解析 HTTP/SSE，不读取环境变量，也不
访问 Kubernetes 或 Prometheus wire protocol；它只组合 discovery、observation、routing 和
circuit。

## 主选择流程

`Path.Select` 现在只有三个阶段：

1. 读取 discovery，并让 routing/circuit/in-flight 看到同一份 membership；
2. 合并观测、local in-flight 和 circuit，执行显式 Service fallback；
3. 为最终 backend 登记一个必须完成的 lease。

Discovery 过期、所有 direct backend circuit open、策略错误和非法 backend 地址分别保留
`discovery-fallback`、`circuit-fallback`、`strategy-fallback` 和 `backend-fallback`，没有用一个
笼统错误掩盖原因。

## 为什么使用 Lease

选择 backend 后，local in-flight 必须在所有退出路径释放。`Lease.Complete(outcome)` 使用
`sync.Once` 保证幂等，因此 delivery 层即使复制 lease 或防御性重复完成，也不会重复扣减计数。

Outcome 明确区分：

- 正常完成响应；
- 建立连接失败；
- upstream deadline；
- response headers 之后的 upstream stream failure；
- client cancellation；
- downstream write failure；
- client 请求无法构造。

只有正常完成和真正的 backend 传输故障进入 circuit。client cancellation、downstream failure
和无效客户端输入保持中性，避免把客户端问题错误归因给 vLLM。

## 成员回收

RequestPath 拥有 active membership 和每 backend atomic in-flight counter：

- backend 离开 discovery 后立即停止新选择；
- 仍有请求时保留计数器和 transport；
- 最后一个 lease 完成后，锁外通知 Gateway 回收 transport client 和 Prometheus labels；
- routing affinity 与 circuit 使用同一份 membership reconcile。

回调特意在释放 requestpath mutex 后执行，避免跨 domain 锁顺序导致死锁。

## Gateway 的变化

Gateway 不再拥有 routing strategy、circuit registry、backend URL map、in-flight map 或 membership
goroutine。代理流程只负责 admission、调用 RequestPath、建立 upstream 请求、复制 SSE，并把
结果交还 lease。Prometheus 指标只是投影 `requestpath.State/Lease/Completion`。

R3 暂时保留 `gateway.NewServer` 创建具体实现；把创建和配置移到 `cmd/fishmesh-gateway` 属于 R4。
