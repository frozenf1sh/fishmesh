# 阶段 57：容量基线与对照实验契约

## 1. 目标

把后续动态 admission、运行时观测和负载感知路由的验证拆成可归因的实验，而不是把多个变量同时打开后比较一个平均延迟。

## 2. 对照轴

### Admission 轴

| Treatment | admission | 路由 | 用途 |
| --- | --- | --- | --- |
| A0 | 当前固定 hard limit | 当前 `load-balanced` | 现状基线 |
| A1 | 离线调优的固定 target | 当前 `load-balanced` | 静态参数上限 |
| A2 | 动态 target | 当前 `load-balanced` | 验证负载变化下的控制收益 |

### Routing 轴

| Treatment | 路由 | admission | 用途 |
| --- | --- | --- | --- |
| B0 | 仅本地 in-flight | 固定 target | 本地计数消融 |
| B1 | vLLM queue/running + 本地事实 | 固定 target | 当前维护主线 |
| B2 | KV-aware，失败回退 B1 | 固定 target | KV locality 与降级正确性 |
| B3 | B1/B2 + 已完成身份映射的 runtime signal | 固定 target | 运行时指标增量收益 |

`session-key` 不作为维护路径或收益主对照，只做兼容回归。

## 3. 运行矩阵

- 容量阶梯：1、2、4、8、16、32 offered QPS；使用 `configs/capacity-ladder.json`。
- 动态控制：低负载 → 中负载 → 高负载 → 低负载；使用 `configs/admission-dynamic-step.json`。
- 路由消融：共享前缀、随机前缀、混合前缀；使用 `configs/routing-ablation.json`。
- 长连接：保持若干 SSE 请求运行，在 target 下调期间确认已有连接不被撤销；使用 `configs/long-connection-drain.json`。
- 每个 treatment 至少重复多轮，固定 workload seed、cache generation、模型、vLLM、Pod 数和 GPU 放置；正式窗口排除 warmup、batch pause 和 scenario gap。

## 4. 必留证据

每轮保留：plan、requests JSONL、report JSON/Markdown、Gateway metrics window、vLLM queue/running、观测 freshness、Pod/GPU 运行时快照和失败分类。报告必须同时列出 offered、accepted、completed 和 rejected rate。

## 5. 成功判据

动态 admission 不能以中断已有 SSE 或简单降低 rejection 换取“成功”。最终同时检查：同一 SLO 下最大可持续 completed QPS、TTFT/E2E P50/P95/P99、rejection/error、Little’s Law 残差、target 振荡/稳定时间，以及活动连接中断数（必须为 0）。

当前单张 time-sliced GPU 只支持相对收益结论，不支持独立 GPU 横向扩展结论。
