# 阶段 35：R6G 默认历史路径修复

> 日期：2026-08-15
> 状态：已完成

## 1. 问题

`fishmesh-client chat` 原先把 `--history` 声明为必填参数。这样客户端的请求和 SSE 单元测试虽然通过，
但实际不带参数启动对话会在发送请求前退出，不能直接用于 KV-aware 模式验收。

## 2. 行为

未指定 `--history` 时，CLI 在启动时生成一次 UTC 纳秒时间戳，并使用：

```text
~/.local/state/fishmesh/<timestamp>.json
```

目录和文件仍由原子 history 保存逻辑创建，文件权限保持 `0600`。每次未指定路径的启动都是独立对话；需要
续接历史时显式传入同一个 `--history`。为避免 `--clear` 对一个刚生成的新文件执行无意义操作，清理命令
仍要求显式指定路径。

## 3. 验证

- `go test ./cmd/fishmesh-client ./internal/workload/client`
- CLI 测试使用临时 HOME 和 SSE 测试服务器，确认省略 `--history` 能完成请求并保存 system/user/assistant history；
- `go test ./...`
- `git diff --check`

本阶段只修复客户端默认历史路径，不切换 Gateway routing mode，也不改变 KV-aware unknown/stale 降级语义。
