# 阶段 62：容量报告与 A/B 收益汇总

## 1. 交付

- benchmark 的每个 batch 和 scenario report 现在保留对应的 Gateway metrics window。
- scenario/batch 窗口继续排除 warmup、batch pause 和 scenario gap；全局窗口仍按 active duration 加权。
- `fishmesh-client compare` 支持可选 `--baseline-report` / `--treatment-report`，汇总 accepted/completed/rejected QPS、平均 in-flight 和 Little’s Law W。
- 既有 request JSONL compare 继续提供 TTFT P50/P95/P99、跨轮中位数和 bootstrap CI；Gateway report evidence 独立标记 valid runs。

## 2. 推荐命令

```bash
fishmesh-client compare \
  --baseline artifacts/bench/a0-r1/requests.jsonl \
  --treatment artifacts/bench/a2-r1/requests.jsonl \
  --baseline-report artifacts/bench/a0-r1/report.json \
  --treatment-report artifacts/bench/a2-r1/report.json \
  --bootstrap 2000 --seed 20260816 \
  --output-dir artifacts/bench/compare-a0-a2
```

多轮运行时重复四类参数；request JSONL 与 report JSON 必须保持同一 run pair。Gateway invalid window 不能被当作零吞吐，必须在报告中保留并重新运行。

## 3. 收益判定

先看正确性和稳定性：成功率、upstream/admission error、已有 SSE 中断、KV degradation correctness、runtime freshness。通过后才比较 TTFT/E2E tail、completed QPS、rejection rate、Little’s Law residual、target 调整稳定时间和振荡次数。

动态 admission 的收益主要在阶梯/突发负载；稳态容量必须同时与最佳离线静态 target 对比。若 active 只降低 rejection 但降低 completed QPS，或破坏已有连接，不判定为收益。
