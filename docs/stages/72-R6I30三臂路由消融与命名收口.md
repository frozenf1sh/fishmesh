# R6I-30：三臂路由消融与命名收口

## 交付

- 将旧本地 `load-balanced` 与消费 vLLM queue/running 的 `load-aware` 拆为两个 mode/policy；
  `load-aware` 成为默认普通路由，外部观测不完整时返回可见的 `load-balanced-v1`。
- 新增请求级 `round-robin-v1`，作为没有调度信号的 Kubernetes Service 近似消融。它不声称复刻
  kube-proxy 的连接级行为；direct Service 保留为独立网络路径对照。
- KV 信号不可用或短上下文旁路时统一进入 `load-aware → load-balanced` 链，并按实际落点发布不同
  fallback policy，避免再用同一个 policy 标签遮蔽算法变更。
- 新增 R6I-30 最小三臂计划、声明式 overlays 与测试 agent prompt；只测试新增 RR/LA/KV 因果轴，
  不重复已完成的长上下文全矩阵。

## Admission 边界

默认 admission tuning 保持 `off`。R6I-25 的 active 单轮没有 hard rejection，target 在 recovery 不会下调；
目前只能证明控制器会升档和 hold，不能证明双向稳定收敛或作为产品默认值。R6I-30 将 admission 固定 off，
避免它成为 RR/LA/KV 的混杂变量。

## 验收

- routing/config/requestpath contract tests 覆盖 RR、LA 选择、LA 降级和 KV fallback provenance；
- `go test -race ./...`、`go vet ./...`、`go build ./...`、`make manifest`、三份 R6I-30 Kustomize dry-run；
- 测试 agent 完成双 replicate、反向顺序、双层滚动隔离、vLLM cache metrics 和三对 compare 后，
  才能给性能 promotion 结论。
